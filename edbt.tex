\begin{abstract}
Fixed-state vector-index measurements miss the cost and quality changes created by
arrival order. UVR-Bench addresses this gap with a paired replay that holds the final
corpus and query identities fixed, interleaves updates with queries, and records exact
neighbors together with event-level work. Across controlled and public GloVe-100
workloads, the protocol reveals when shifted arrivals create partition mismatch and
when rebuilding recovers quality at a substantial maintenance cost. At a fixed low
search budget, rebuilding improves recall for the shifted semantic stream, but
recall-floor selection shows that increasing search work on a fixed index can be cheaper
than rebuilding. The released logs, hashes, and independent checks make these
conditional trade-offs reproducible and auditable. A 100k-vector HotpotQA
document-semantic extension shows a near-zero order effect, marking the boundary of the
claim beyond the constructed GloVe shift. A native 1M-vector replay broadens the
validation to dynamic implementations; host-memory FreshDiskANN and SPFresh evidence
is reported with its hardware boundary, and unavailable systems are not assigned
substituted numbers.
\end{abstract}

\section{Artifacts}
The read-only supplementary artifact is available at
\url{https://anonymous.4open.science/r/edbt2027-7FD5/README.md}.
It contains the Python implementation, pinned requirements, public input data,
lifecycle, scale and rebuild-schedule workloads, fixed seeds, raw JSON logs, figures,
native logs/configs, hash ledgers, and offline CPU
reproduction commands. The verifier recomputes exact
neighbors and Recall@10, checks role disjointness, workload counts, rebuild rounds and
service totals, and compares event logs with the reported summaries. Timing values may
vary across machines, while source and data hashes should agree. The mirror requires no
reviewer authentication and contains no author-identifying metadata.
